# FireflyTools 用户体验重点问题清单

> 整理日期：2026-08-21
>
> 评审视角：普通用户完成媒体下载、文件整理和图片处理任务时的安全性、可控性与可理解性
>
> 文档性质：问题清单与改进依据，不代表相关功能已经进入实施阶段

## 1. 优先级说明

| 优先级 | 含义 |
| --- | --- |
| P0 | 可能导致用户文件被误移动、误覆盖或难以恢复，应优先处理 |
| P1 | 明显影响任务可控性、结果可发现性或批量处理体验，应在公开交付前处理 |

## 2. 问题总览

| 编号 | 优先级 | 问题 | 主要影响模块 |
| --- | --- | --- | --- |
| UX-001 | P0 | 文件移动操作缺少预览、确认和撤销依据 | 视频子目录提取、关键字归档 |
| UX-002 | P0 | 视频与图片输出存在静默覆盖风险 | 视频下载、图片智能裁剪 |
| UX-003 | P1 | 视频下载任务缺少运行状态和控制入口 | 视频下载爬虫 |
| UX-004 | P1 | 下载成功后不方便定位输出文件 | 视频下载爬虫 |
| UX-005 | P1 | 图片批量处理可能阻塞界面且失败信息不可见 | 图片智能裁剪 |
| UX-006 | P1 | 用户设置和等待任务无法跨重启保留 | 主窗口、四个工具页 |

## 3. P0：文件安全问题

### UX-001：文件移动操作缺少安全防线

#### 当前表现

- “视频子目录提取”点击开始后会直接把子目录中的视频移动到根目录。
- “视频子目录提取”默认启用“完成后删除空的子文件夹”。
- “关键字归档”点击开始后会直接把匹配文件移动到关键字目录。
- 操作开始前不展示待移动文件清单、目标路径和预计影响数量。
- 操作完成后没有可供恢复的操作记录，也没有撤销入口。
- 关键字会直接参与目标目录路径构造，缺少面向用户的目录名合法性提示。

相关源码：

- `tools/video_extractor.py`
- `tools/keyword_organizer.py`

#### 用户影响

- 用户可能在未理解操作范围的情况下批量改变原始目录结构。
- 错误关键字或错误根目录可能造成大量文件被移动。
- 自动删除空目录会进一步增加恢复原目录结构的难度。
- 虽然已有重名自动改名逻辑，但用户无法在执行前确认最终文件名。

#### 建议方案

1. 增加“扫描预览”阶段，先显示匹配数量、来源路径、目标路径和重名处理结果。
2. 在预览确认后才允许执行实际移动。
3. 默认关闭“删除空目录”，或在执行前单独二次确认。
4. 保存本次移动映射清单，至少支持人工恢复；条件允许时提供一次性撤销。
5. 对关键字进行目录名校验，拒绝空白、绝对路径、路径分隔符和 Windows 非法字符。

#### 建议验收标准

- 未经过预览确认时不会移动或删除任何文件。
- 界面能准确显示将移动、重命名和删除的数量。
- 关键字不能逃逸所选根目录。
- 每次执行都能生成来源路径到目标路径的操作记录。

### UX-002：输出文件存在静默覆盖风险

#### 当前表现

- 视频下载页只检查保存名称是否为空，没有完整校验非法文件名、路径分隔符或已有同名文件。
- Direct MP4 路径使用写入模式创建目标文件，同名文件可能被直接覆盖。
- HLS、DASH 和 yt-dlp 最终也可能指向相同的用户命名输出。
- 图片裁剪按“原文件名_宽x高.jpg”生成固定名称，目标目录中存在同名文件时可能被覆盖。

相关源码：

- `tools/video_downloader.py`
- `tools/video_crawler/adapters/direct_mp4.py`
- `tools/video_crawler/adapters/hls.py`
- `tools/video_crawler/adapters/dash.py`
- `tools/image_resizer.py`

#### 用户影响

- 用户已有的视频或图片可能在没有明确提示的情况下被替换。
- 多个同名任务可能互相覆盖结果，队列汇总仍只显示任务成功。
- 保存名称包含路径字符时，输出位置可能偏离用户预期。

#### 建议方案

建立统一输出冲突策略：

1. 默认采用“自动重命名”，例如追加 `_1`、`_2`。
2. 可选“每次询问”或“明确覆盖”，但覆盖必须由用户主动选择。
3. 视频任务入队前校验保存名称，禁止绝对路径、父目录跳转和平台非法字符。
4. 图片批处理在开始前计算全部目标名称，并在预览中标出冲突。
5. 所有下载适配器通过同一个输出路径分配函数获得最终路径，避免各自实现不同策略。

#### 建议验收标准

- 默认设置下不会覆盖任何已有文件。
- 同名任务会得到不同输出路径，并在结果中显示真实文件名。
- 非法保存名称会在入队前给出明确、可操作的提示。
- MP4、HLS、DASH、yt-dlp 和图片处理使用一致的冲突语义。

## 4. P1：任务可控性与结果反馈问题

### UX-003：视频下载任务缺少运行状态和控制入口

#### 当前表现

- 工作线程取出任务后，任务会立即从“等待队列”列表消失。
- 用户主要依赖文本日志判断当前正在处理哪个任务以及处理到哪个阶段。
- 没有稳定的当前任务卡片、总体进度、切片进度或预计剩余时间。
- 没有暂停、取消、删除等待任务或调整队列顺序的入口。
- 关闭主窗口时没有正在执行任务的确认提示。

相关源码：`tools/video_downloader.py`

#### 用户影响

- 长时间嗅探、下载或 FFmpeg 合并时，用户容易误以为程序卡死。
- 加错任务后无法在界面中撤销，只能等待或直接关闭程序。
- 关闭程序可能中断当前任务；即使断点切片被保留，用户也没有清楚的恢复提示。

#### 建议方案

1. 将任务分为“等待中、嗅探中、下载中、合并中、已完成、失败、已取消”等状态。
2. 保留当前执行任务的可见卡片，不要在取出队列后直接从界面消失。
3. 先增加安全取消：停止后保留可恢复切片，并在结果中说明是否可继续。
4. 支持删除尚未执行的等待任务。
5. 关闭窗口时若有运行或等待任务，显示任务数量和中断后果。
6. 有可靠总量时展示确定进度；无法估计时使用阶段状态和不确定进度动画。

#### 建议验收标准

- 用户始终能看到当前任务、当前阶段和等待任务数量。
- 等待任务可以在执行前移除。
- 取消和关闭不会静默删除可恢复切片。
- 任务结束后状态不会仅存在于日志中。

### UX-004：下载成功后不方便定位输出文件

#### 当前表现

- 下载结果字典保存了 `output_path`。
- 批次成功摘要只显示任务名称，不显示最终绝对路径。
- 成功弹窗没有“打开文件”“打开所在文件夹”或“复制路径”操作。
- 输出目录默认值依赖程序启动时的当前工作目录。

相关源码：`tools/video_downloader.py`

#### 用户影响

- 用户看到“成功”后仍可能找不到文件。
- 从非项目根目录启动时，默认输出位置更容易与预期不一致。
- 多任务批次中难以逐项确认实际输出文件。

#### 建议方案

1. 成功摘要显示实际输出文件名和规范化后的绝对路径。
2. 增加“打开所在文件夹”“打开文件”和“复制路径”按钮。
3. 默认下载目录改为稳定的用户目录或应用数据中保存的上次目录，不依赖当前工作目录。
4. 队列任务完成后在任务卡片中保留输出路径入口。

#### 建议验收标准

- 每个成功任务都能从结果界面一键定位输出文件。
- 不论从哪个目录启动程序，默认保存位置都保持一致且清楚可见。
- 路径不存在或打开失败时给出明确错误，而不是静默失败。

### UX-005：图片批量处理体验不可靠

#### 当前表现

- 图片处理循环运行在 Qt 主线程，通过 `QApplication.processEvents()`维持界面响应。
- 大图片或大量文件可能造成明显卡顿。
- 单张图片处理失败时只输出到控制台，界面不记录失败文件和原因。
- 最终弹窗只报告成功数量，容易让用户忽略失败项。
- 没有进度条、取消操作或处理前输出冲突预览。

相关源码：`tools/image_resizer.py`

#### 用户影响

- 批量任务期间界面可能响应迟缓，用户无法判断是否仍在工作。
- 部分文件失败时，用户需要自行逐一比对输入和输出。
- 用户无法中止错误参数导致的大批量任务。

#### 建议方案

1. 将图片处理迁移到工作线程，通过 Qt 信号更新进度和结果。
2. 展示“已处理/总数”、当前文件和成功/失败计数。
3. 提供取消按钮，并保证当前文件写入完成后安全停止。
4. 在结果弹窗中列出失败文件和错误原因，并支持复制或导出清单。
5. 开始前完成目标名称冲突检查。

#### 建议验收标准

- 处理大量图片时主窗口仍可正常移动、切换和取消。
- 最终结果同时展示成功数、失败数和失败原因。
- 取消后已生成文件保持有效，未处理文件不会产生空输出。

### UX-006：设置和任务无法跨重启保留

#### 当前表现

当前没有统一的用户配置持久化机制。以下信息在关闭程序后会恢复默认或丢失：

- 当前壁纸。
- 最近使用的保存目录和输入目录。
- 视频下载模式、并发数、断点续传、yt-dlp 和嗅探选项。
- 图片目标尺寸、裁剪重心和输出目录。
- 尚未执行的等待队列。

相关源码：

- `tools/main.py`
- `tools/video_downloader.py`
- `tools/video_extractor.py`
- `tools/keyword_organizer.py`
- `tools/image_resizer.py`

#### 用户影响

- 重复使用时需要反复填写相同设置。
- 程序异常退出或主动重启后，等待任务无法恢复。
- 用户难以建立稳定的个人工作流。

#### 建议方案

1. 使用 `QSettings` 保存低风险界面偏好和最近目录。
2. 等待队列使用独立 JSON 文件持久化，任务开始、取消或完成时原子更新。
3. 不持久化明文 Cookie、Authorization 或浏览器敏感数据；浏览器会话继续由专用 profile 管理。
4. 增加“恢复默认设置”和“清空等待队列”入口。
5. 配置读取失败时回退默认值，并保留可诊断日志。

#### 建议验收标准

- 正常重启后恢复壁纸、最近目录和常用选项。
- 异常退出后，未开始的任务可以恢复；已运行任务不会被误标为成功。
- 配置文件损坏不会阻止程序启动。
- 敏感浏览器凭据不会写入普通设置文件。

## 5. 推荐实施顺序

1. **第一阶段：文件安全**：完成 UX-001 和 UX-002，先消除误移动与静默覆盖风险。
2. **第二阶段：下载闭环**：完成 UX-003 和 UX-004，让用户看得见、停得下、找得到结果。
3. **第三阶段：本地批处理体验**：完成 UX-005，补齐图片处理的线程、进度和失败反馈。
4. **第四阶段：持续使用体验**：完成 UX-006，保存设置并恢复未执行任务。

## 6. 实施约束

- 所有文件移动、删除和覆盖行为必须以用户明确可见的方式发生。
- 不得删除用户下载产物、断点续传切片、浏览器 profile 或来源不明文件。
- 新行为应先补失败测试，再进行最小实现。
- 现有视频爬虫结构化错误、日志脱敏和断点续传语义必须保持。
- UI 改动应继续兼容动态主题，并覆盖小窗口、长路径和批量任务场景。
- 当前工作区已有未提交源码、测试和文档改动，实施时不得还原或覆盖。
