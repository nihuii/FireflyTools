# 图片相似度深度视觉特征设计方案

> 日期：2026-08-23
>
> 状态：已批准，等待书面规格复核
>
> 适用项目：FireflyTools（Python 3.13 / PyQt6 / Pillow）

## 1. 背景

FireflyTools 的图片相似度检测目前使用 SHA-256、pHash、dHash、宽高比、小尺寸灰度描述符和预乘 RGBA 描述符。三个档位通过固定阈值执行合取判断：只要某一项不满足，图片对就不会被判定为相似。

`pic_test` 中的两张本地验收图片具有相同人物、近似动作和表情、近似构图，仅头部角度及少量局部细节不同。现有指标为：

- pHash 汉明距离：12；
- dHash 汉明距离：13；
- 宽高比差异：0；
- 灰度相似度：约 0.9398；
- RGBA 相似度：约 0.9703。

严格档当前要求 pHash 和 dHash 距离都不大于 4，因此会在传统哈希阶段直接拒绝该图片对。这说明现有算法适合检测重新编码、轻度缩放等近重复图片，但不能可靠理解“同一人物、同一动作和构图，只发生轻微姿态变化”的视觉关系。

本设计引入本地深度视觉特征，同时保留现有经典指纹及回收站安全边界。目标不是进行人脸识别、人物身份数据库或远程 AI 服务，而是更准确地识别适合人工复核的高度相似图片。

## 2. 目标

1. 让人物动作、表情和构图高度一致、仅存在轻微转头或局部重绘的图片进入严格档候选。
2. 保留完全重复和经典近重复检测，不降低现有确定性结果的可靠性。
3. 使用全局与局部视觉证据，避免仅因主体相同就把不同动作、不同场景归为严格相似。
4. 保持严格结果包含于标准结果、标准结果包含于宽松结果。
5. 支持一万张以内图片的目录扫描，不执行全量平方级 Python 图片对比较。
6. 模型完全在本机推理；图片不上传；模型下载必须由用户明确触发并校验完整性。
7. 模型缺失、损坏、推理失败、图片变化或用户取消时不得导致进程闪退或产生不完整的正式结果。
8. 所有删除复选框继续默认不选中；深度模型结果不能绕过现有文件快照和回收站复核。

## 3. 非目标

- 不做人脸识别、人物身份确认或人物资料库。
- 不把宽松档内容相关图片定义为可安全删除的重复图片。
- 不自动勾选或自动移入回收站。
- 不调用云端图像理解或上传图片。
- 不在首版训练或微调模型。
- 不在 Git 仓库提交 `pic_test` 原图。
- 不在单元测试中联网或自动下载模型。
- 不以 DINOv3 作为首版运行模型。
- 不为全部图片持久保存局部 Patch 特征。

## 4. 已确认决策

| 项目 | 决策 |
| --- | --- |
| 首版模型 | DINOv2 ViT-S/14 |
| 推理运行时 | ONNX Runtime CPU |
| 模型取得 | 首次使用时由用户明确确认下载 |
| 模型校验 | 固定版本、SHA-256、输出维度和预处理版本全部校验 |
| 图片处理 | 全程本机执行，不上传 |
| 全局特征 | 所有成功解码的非重复内容计算，并允许按内容哈希缓存 |
| 局部特征 | 仅对候选图片按需计算，使用有界内存缓存 |
| 最终判断 | 深度全局、局部、空间一致性与经典证据组合 |
| 传统哈希 | 继续作为确定性分支和佐证，不再对深度严格分支一票否决 |
| 宽松档批量操作 | 智能内容相关组不提供无警告的一键批量选择 |
| 本地验收图片 | 保持未跟踪，只做本地验收 |

## 5. 模型选择

### 5.1 DINOv2 ViT-S/14

DINOv2 ViT-S/14 约 21M 参数，输出 384 维全局特征，并能提供局部 Patch token。模型特征适合图像检索和下游视觉任务；Apache 2.0 许可也比受限权重更便于桌面程序部署。

正式程序只加载经过验证的 ONNX 模型，不引入 PyTorch。ONNX 模型由开发流程从固定的官方 DINOv2 权重导出，并必须通过同一输入下与参考实现的输出一致性测试。DINOv2 官方仓库并未把本项目需要的 ONNX 文件作为运行时保证，因此导出兼容性是实施前置门槛。

模型参考：

- <https://github.com/facebookresearch/dinov2>
- <https://github.com/facebookresearch/dinov2/blob/main/MODEL_CARD.md>
- <https://onnxruntime.ai/docs/get-started/with-python.html>

### 5.2 暂不采用 DINOv3

DINOv3 的密集视觉特征具有后续评测价值，但其权重访问和许可发行流程更复杂。首版先建立与模型无关的后端接口、校准语料和验收方法；DINOv3 只作为未来可替换后端，不进入当前实施范围。

### 5.3 暂不采用 LPIPS 或纯语义模型

LPIPS 更适合比较已经对齐的图像失真，不能独立解决局部姿态变化。纯全局语义模型容易把同一人物的不同动作、不同场景归为相似，不符合严格档面向安全人工筛选的目标。它们可以作为未来评测项，但不作为首版判定核心。

## 6. 三个档位定义

### 6.1 严格档

面向用户的定义：同一主体，动作、表情和构图高度一致；允许轻微转头、局部重绘、压缩、色偏和小幅裁剪。

图片对满足以下任一分支即通过：

1. SHA-256 完全相同；
2. 现有经典严格档完整通过；
3. 深度严格分支同时满足：
   - 全局特征相似度达到严格阈值；
   - 局部 Patch 双向匹配覆盖率达到严格阈值；
   - 局部匹配的空间一致性达到严格阈值；
   - 至少一种经典佐证成立，例如宽高比接近、灰度/RGBA 较高、裁剪鲁棒哈希匹配或传统哈希处于放宽的候选范围。

pHash 或 dHash 单项超过原严格阈值不能否决深度严格分支。`pic_test` 目标图片对必须作为严格档本地验收样本。

### 6.2 标准档

面向用户的定义：同一主体和相近场景，动作、表情、裁剪或局部构图存在中等变化。

标准档沿用严格档的三个确定性分支，并降低全局、局部覆盖和空间一致性要求。深度分支仍要求局部证据；空间一致性和经典佐证至少满足一项，防止仅凭全局主体相似通过。

### 6.3 宽松档

面向用户的定义：内容、人物或场景明显相关，允许姿态、背景和构图发生较大变化，用于发现候选而非确认重复。

宽松档以全局特征和部分局部匹配为主。此档产生的深度关系标记为“智能内容相关”，UI 必须突出人工复核提示，并限制无提示的一键批量选择。

### 6.4 单调性

深度阈值必须满足以下单调关系：

```text
严格全局阈值 > 标准全局阈值 > 宽松全局阈值
严格局部阈值 > 标准局部阈值 > 宽松局部阈值
严格空间阈值 > 标准空间阈值 > 宽松空间阈值
```

最终回归测试必须验证：

```text
严格结果集合 ⊆ 标准结果集合 ⊆ 宽松结果集合
```

具体数值不能在模型尚未导出和实测前凭经验写死，必须通过第 14 节校准流程产生，并与模型及预处理版本绑定。

## 7. 总体架构

系统分为六个职责清晰的单元：

1. **模型管理器**：维护模型清单、下载确认、校验、状态和路径。
2. **深度特征后端**：执行固定预处理、ONNX 推理和输出校验。
3. **全局候选索引**：从全局向量生成近邻候选，避免 Python 全量两两比较。
4. **局部匹配器**：执行 Patch 双向最近邻匹配和空间一致性计算。
5. **证据融合器**：根据档位把经典与深度证据转换为关系类型。
6. **扫描协调器和 UI**：管理阶段、进度、取消、错误、结果展示和安全操作。

经典指纹模型与深度特征存储分离。`ImageFingerprint` 继续代表扫描时文件快照和经典指纹；深度向量由独立存储按内容哈希和模型版本索引，避免把大数组混入回收站安全模型。

## 8. 数据模型

新增概念模型：

- `DeepModelSpec`：模型 ID、版本、URL、SHA-256、输入尺寸、输入/输出名称、特征维度、预处理版本和许可文件。
- `DeepModelStatus`：未安装、下载中、校验中、就绪、损坏、不兼容。
- `DeepGlobalDescriptor`：内容 SHA-256、模型版本、归一化的全局向量。
- `DeepPatchDescriptor`：归一化 Patch 向量及网格尺寸，只在候选验证期间存在。
- `SimilarityEvidence`：全局分数、局部覆盖率、空间一致性、经典佐证和最终关系。
- `SimilarityRelation`：完全相同、经典近重复、智能高度相似、智能内容相关。
- `DeepSimilarityThresholds`：三个档位各自的全局、局部、空间和佐证规则。

特征数组使用 NumPy 数组在内部传递，公共结果模型只保存标量证据和稳定标识，不把 ONNX Runtime 会话或大数组暴露给 UI。

## 9. 图像预处理与模型输出

深度预处理必须版本化，并固定执行：

1. 使用 Pillow 打开图片并完整解码；
2. 对异常 EXIF 使用现有警告隔离策略；
3. 执行 `ImageOps.exif_transpose()`；
4. 转换为 RGB；
5. 使用与模型导出一致的缩放、裁剪和归一化；
6. 生成连续 `float32` NCHW 张量；
7. 运行 ONNX 会话；
8. 校验输出名称、维度、有限值和 L2 范数；
9. 对全局和 Patch 特征分别做 L2 归一化。

正式运行时以参考实现的预处理为基准。若输入大小或裁剪策略变化，必须提升预处理版本并使旧缓存失效。

## 10. 候选生成与局部验证

### 10.1 候选并集

候选图片对来自以下来源的并集：

- 现有 pHash/dHash BK-tree 的放宽候选半径；
- 灰度、RGBA 和裁剪鲁棒指纹候选；
- DINOv2 全局特征近邻索引。

全局向量先通过固定、可复现的降维映射进入现有 NumPy/SciPy 可承载的近邻索引，再对候选使用原始 384 维向量计算精确余弦相似度。降维维数、邻居数量和候选召回率必须由评测决定，不能成为最终判定阈值。

禁止用 Python 双层循环比较全部图片对。实现必须记录候选边数量和各来源命中数量，以便性能回归和召回问题诊断。

### 10.2 Patch 匹配

仅为通过全局初筛或经典候选初筛的图片提取 Patch 特征。对于每个候选图片对：

1. 计算 Patch 余弦相似度矩阵；
2. 保留双向最近邻匹配；
3. 排除低相似度匹配；
4. 计算两侧 Patch 覆盖率；
5. 将 Patch 网格坐标归一化到 `[0, 1]`；
6. 通过稳健中位位移和内点比例计算空间一致性；
7. 输出局部覆盖率、空间一致性和匹配数量。

首版不引入 OpenCV 或复杂单应性估计。轻微转头和局部变化应保留足够多的一致 Patch；同一人物但动作、布局明显不同的图片通常会降低覆盖率或空间一致性。

## 11. 分组与关系解释

证据融合器按第 6 节规则产生关系。严格和标准档通过深度分支的结果标记为“智能高度相似”；宽松档只通过较低深度阈值的结果标记为“智能内容相关”。

分组继续使用代表图片直接匹配：每个成员必须与该组代表图片直接满足当前档位，不能通过 A≈B、B≈C 推导 A≈C。完全重复簇先折叠，再参与代表选择和相似分组。

UI 展示简化证据等级，而不是向普通用户直接暴露难解释的小数阈值，例如：

```text
智能高度相似
全局：高　局部：高　构图：高　经典佐证：灰度/裁剪
```

## 12. 模型下载、缓存与离线行为

模型管理器读取随程序发布的清单。首次智能扫描遇到模型未安装时，UI 展示模型名称、大小、许可链接和“下载并安装”按钮；只有用户确认后才开始下载。

下载要求：

- 写入临时文件，完成 SHA-256 校验后再原子替换正式模型；
- 取消或失败时不留下可被误认为有效模型的文件；
- 模型和全局特征缓存位于应用用户数据目录，不写入项目仓库；
- 不执行下载内容中的代码；
- 模型清单固定 HTTPS 地址和 SHA-256；
- 校验失败时标记为损坏并允许重新下载。

全局特征缓存以 `(内容 SHA-256, 模型 ID, 模型版本, 预处理版本)` 为键。缓存只保存全局 `float32` 向量和必要元数据；读取时重新校验维度和有限值。局部 Patch 特征使用有容量限制的内存 LRU，扫描完成、取消或模型变化时释放。

用户拒绝下载或当前离线时，可以明确选择“仅使用经典算法扫描”。UI 必须标记此次结果未使用智能特征，不能把经典扫描伪装成智能扫描。

## 13. 扫描流程、进度和取消

扫描阶段扩展为：

1. 枚举图片；
2. 经典视觉指纹；
3. 完整内容哈希；
4. 全局深度特征；
5. 候选生成；
6. 局部智能复核；
7. 分组；
8. 缩略图和结果；
9. 完成或取消。

经典指纹继续使用有限线程池。ONNX Runtime 会话由单一后端对象持有；CPU 推理从保守的单会话、小批次开始，通过基准测试后才调整并发。进度必须按成功、缓存命中、失败和总数更新，并在每个批次及候选对之间检查取消事件。

取消后返回 `cancelled=True` 和空正式分组。半成品特征可以安全写入通过完整校验的内容缓存，但不能作为正式 UI 结果展示。

## 14. 阈值校准与评测

### 14.1 数据集

评测集至少覆盖：

- 同图重编码、缩放、轻裁剪、色偏和压缩；
- 同一人物的轻微转头、表情变化和局部重绘；
- 同一人物的明显不同动作；
- 同一人物的不同场景；
- 相同背景但不同主体；
- 相似配色、文字布局或画风但内容不同；
- 遮挡、透明图片、超大图片和损坏图片。

`pic_test` 两张原图只作为本地严格档验收，不提交仓库。自动化单元测试使用程序生成的小图、特征替身和经过授权的微型固定样本。

### 14.2 校准顺序

1. 冻结模型文件、ONNX 导出、预处理版本和特征归一化方法；
2. 计算全部标注图片对的全局、局部、空间和经典证据；
3. 优先选择严格档高精确率边界；
4. 在严格档边界之外确定标准档平衡边界；
5. 在保证单调性的前提下确定宽松档召回边界；
6. 对候选索引单独测量候选召回率，保证最终可通过的图片对不会在候选阶段丢失；
7. 将阈值和模型/预处理版本共同固化；
8. 模型或预处理变化时重新执行全部评测。

### 14.3 首版验收

- `pic_test` 目标图片对在严格档形成一个组；
- 难负样本不进入严格档；
- 三档结果满足集合包含关系；
- 单元测试使用假后端时确定性通过；
- 安装模型后的本地黄金测试通过；
- 一万张合成特征的候选生成不退化为 Python 全量两两比较；
- 模型未安装、损坏、输出异常和推理异常都返回结构化结果而不闪退；
- 扫描取消不展示半成品分组；
- 原有完整测试套件继续通过。

## 15. UI 设计

严格档继续作为默认值。档位说明更新为：

- 严格：同主体、同动作和同构图的高置信近似图片；
- 标准：主体和场景相近，允许中等姿态或裁剪变化；
- 宽松：发现内容相关图片，需要人工确认。

页面增加以下状态：

- 智能模型：未安装、下载中、校验中、就绪、损坏或不兼容；
- 本次扫描模式：智能混合扫描或仅经典算法；
- 扫描阶段：全局特征、候选生成和局部智能复核；
- 关系标签：完全相同、经典近重复、智能高度相似、智能内容相关；
- 证据摘要：全局、局部、构图和经典佐证的高/中等级。

“智能内容相关”组点击批量选择时必须先显示额外风险提示；严格和标准档仍保持默认不选中。主题、透明背景、主线程 `QPixmap` 规则和现有打开图片行为保持不变。

## 16. 错误处理

新增结构化错误至少包括：

- 模型未安装；
- 用户拒绝下载；
- 模型下载失败；
- 模型校验失败；
- ONNX Runtime 不可用；
- 模型输入/输出不兼容；
- 推理内存不足；
- 推理输出包含非有限值；
- 深度特征缓存损坏；
- 图片在推理期间发生变化。

单张图片解码或推理失败只记录该图片失败并继续其他图片；模型级错误终止智能扫描并允许用户明确选择经典扫描。模型级失败不能静默改变档位含义。所有异常必须在工作线程边界转换为信号或结果对象，不能穿过 Qt 事件循环造成进程终止。

## 17. 文件边界

## 18. 风险与缓解

| 风险 | 缓解措施 |
| --- | --- |
| 动漫图片与模型训练域存在差异 | 先用本地目标和难负样本校准；模型选择通过同一评测接口可替换 |
| 同一人物不同动作误报 | 严格档强制局部覆盖率和空间一致性 |
| CPU 推理时间较长 | 全局内容缓存、小批次推理、局部特征按候选计算 |
| 候选索引漏召回 | 经典和深度候选取并集，并独立测试候选召回率 |
| 模型文件较大或下载损坏 | 明确下载、临时文件、SHA-256 和原子安装 |
| 模型升级导致阈值漂移 | 模型、预处理、缓存和阈值共同版本化 |
| 宽松档被误当作重复 | 使用独立关系标签、额外提示和批量选择限制 |
| ONNX 导出输出不一致 | 把参考输出一致性作为实施前置门槛 |
| 用户图片在扫描后变化 | 保留现有扫描快照和回收站前复核 |

## 19. 实施顺序

实施计划应按以下可独立验证的阶段展开：

1. 数据模型、模型清单和假后端接口；
2. 模型管理、下载确认和完整性校验；
3. ONNX 预处理、推理和参考输出一致性门槛；
4. 全局特征缓存和近邻候选索引；
5. Patch 匹配、空间一致性和证据融合；
6. 分组和扫描流程集成；
7. UI 模型状态、进度、关系解释和宽松档安全交互；
8. 校准工具、本地目标验收、完整回归和性能验证。

每个阶段使用测试驱动开发并独立提交。模型二进制文件、下载临时文件、全局缓存、`pic_test` 原图和来源不明文件不得进入提交。
