# 视频爬虫新手学习指南设计

## 目标

为具备 Python 基础、但刚开始学习网络爬虫的读者编写一份 FireflyTools 视频爬虫学习指南。读者应能按一次下载任务的真实执行顺序阅读代码，理解各模块的职责、它们之间的数据流，以及代码所涉及的主要网络与流媒体协议。

## 读者基础

- 能阅读 Python 类、函数、异常处理和基本类型标注。
- 知道 HTTP 请求与响应的基本概念，但不要求熟悉浏览器自动化或流媒体协议。
- 不要求掌握 PyQt6、asyncio、HLS、DASH、FFmpeg 或密码学。

## 组织方案

采用“任务链路式”组织正文：从 UI 创建任务开始，沿队列、核心编排、网页嗅探、媒体候选选择、适配器分发、协议下载、断点恢复、FFmpeg 合并和结果回传一路阅读。

每个阶段固定回答以下问题：

1. 这一层解决什么问题。
2. 应阅读哪些文件、类和函数。
3. 数据从哪里来，又被传到哪里。
4. 需要先理解哪些协议或 Python 概念。
5. 初读时哪些实现细节可以暂时跳过。
6. 可以运行什么测试或做什么小练习验证理解。

## 正文结构

1. 学习前准备：运行环境、启动命令、合法使用边界和推荐阅读方法。
2. 一张总链路图：展示 UI 到下载产物和错误结果的完整调用方向。
3. 第一遍阅读：模型、错误、适配器协议和最短 MP4 下载链路。
4. 第二遍阅读：UI 队列如何把参数快照交给后台任务。
5. 第三遍阅读：`UniversalVideoSpider` 如何分类 URL、嗅探网页并选择候选。
6. 第四遍阅读：Playwright 网络监听、浏览器会话继承和访问受限诊断。
7. 第五遍阅读：HLS master/media playlist、切片、加密、BYTERANGE、fMP4、多轨、直播和断点续传。
8. 第六遍阅读：DASH MPD、Representation、SegmentTemplate、音视频分轨和 mux。
9. 第七遍阅读：FFmpeg、输出验证、结构化错误、脱敏和 UI 结果回传。
10. 测试地图、循序练习、常见误区和二次阅读路线。

## 协议讲解范围

- URL、HTTP 方法、状态码、请求头、响应头、Content-Type、Range 和超时重试。
- Cookie、User-Agent、Referer、Origin、LocalStorage，以及浏览器会话与下载请求的关系。
- MP4 直链与渐进式下载。
- HLS 的 M3U8、master playlist、media playlist、variant、media sequence、TS、AES-CBC、IV、EXT-X-BYTERANGE、EXT-X-MAP、fMP4、DISCONTINUITY、音轨、字幕和直播 playlist。
- DASH 的 MPD、Period、AdaptationSet、Representation、BaseURL、SegmentTemplate、初始化分段和媒体分段。
- FFmpeg remux/mux 与重新编码的区别。
- DRM 的识别与项目不绕过访问控制的边界。

协议说明以项目当前实现为准，不扩展成完整标准手册；每个概念都绑定到实际源文件和函数。

## 表达规范

- 使用中文，首次出现的英文缩写给出中文解释。
- 文件路径、类名、函数名和命令使用代码格式。
- 优先使用短段落、表格和 Mermaid 流程图，避免大段源码复制。
- 明确区分“第一遍必须读”“第二遍再读”和“暂时跳过”。
- 对复杂模块先给心智模型，再进入函数级阅读顺序。
- 不把下载受限内容、绕过 DRM、验证码或权限控制作为练习目标。

## 完成标准

- 文档保存为 `docs/视频爬虫新手学习指南.md`。
- 文档中的所有源码路径和测试文件在当前仓库中真实存在。
- 阅读顺序覆盖 UI、编排、嗅探、候选选择、MP4、HLS、DASH、恢复、合并、错误和结果回传。
- 所列协议均说明“它是什么、为何在本项目出现、对应哪段代码”。
- 初学者可以只按第一遍路线先跑通最短链路，再逐步进入 HLS/DASH 复杂实现。
