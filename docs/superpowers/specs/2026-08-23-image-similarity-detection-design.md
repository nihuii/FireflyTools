# 图片相似度检测第一版设计方案

> 日期：2026-08-23
>
> 状态：第一版设计，待用户复核文档
>
> 适用项目：FireflyTools（Python 3.10+ / PyQt6 / Pillow）

## 1. 背景

FireflyTools 当前通过 `tools/main.py` 组装四个标签页，其中图片能力仅包含 `tools/image_resizer.py` 的批量裁剪与缩放。用户需要增加一个独立的“图片相似度检测”功能：扫描指定目录，将完全重复或视觉相似的图片分组列出，由用户逐张选择后移入系统回收站。

这个功能涉及大量图片解码、相似度误判和文件删除，因此第一版必须优先保证以下边界：

- 扫描阶段只读，不修改任何用户文件。
- 相似图片只负责分组和建议，不自动选择删除项。
- 删除只允许移入系统回收站，不提供永久删除或失败后的永久删除降级。
- 删除前展示所选文件的完整路径并二次确认。
- 页面沿用现有动态壁纸主题，不能用不透明区域遮挡背景图。
- 一次扫描以一万张图片以内为主要目标，不能采用全量平方级两两比较。

## 2. 目标

第一版需要提供以下能力：

1. 选择一个根目录并按需递归扫描子目录。
2. 识别并区分“完全重复”和“视觉相似”图片。
3. 提供严格、标准、宽松三档相似度预设，默认严格。
4. 将相似图片按组展示，并标注一张“建议保留”图片。
5. 所有删除复选框默认未选中，由用户逐张选择。
6. 删除前复核文件状态并显示二次确认窗口。
7. 使用系统回收站处理选中图片，逐项返回成功、失败或跳过结果。
8. 扫描、分组和缩略图处理运行在后台，支持进度和安全取消。
9. UI 兼容当前浅色、深色和无壁纸主题，并保持背景可见。

## 3. 非目标

第一版明确不包含：

- 永久删除文件。
- 扫描完成后自动勾选任何删除项。
- 同时添加多个互不相关的根目录。
- 向普通用户暴露哈希距离等数值阈值。
- AI 语义相似、场景分类、人脸识别或人物聚类。
- 对大幅裁剪、构图明显变化或连拍动作变化进行自动重复判定。
- 内置图片编辑器或全屏预览器；查看原图调用系统默认程序。
- 跨重启保存扫描结果或建立持久化指纹数据库。
- 后台监控目录和自动增量扫描。
- 清空系统回收站。

## 4. 已确认的产品决策

| 项目 | 第一版决策 |
| --- | --- |
| 删除方式 | 仅移入系统回收站 |
| 删除确认 | 展示数量、所选总大小和完整路径后再次确认 |
| 扫描入口 | 单个根目录 |
| 子目录 | 可选，默认开启 |
| 结果类型 | 完全重复、视觉相似 |
| 默认灵敏度 | 严格 |
| 删除默认选择 | 全部未选中 |
| 建议保留 | 系统标注，但不限制用户最终选择 |
| 主要规模 | 一万张图片以内 |
| UI 位置 | 主窗口第 5 个标签页“图片相似度检测” |
| UI 风格 | 动态主题、半透明悬浮面板、背景图持续可见 |

## 5. 用户流程

### 5.1 选择并扫描

1. 用户进入“图片相似度检测”标签页。
2. 用户选择一个根目录。
3. 用户决定是否包含子文件夹，默认包含。
4. 用户选择严格、标准或宽松，默认严格。
5. 用户点击“开始扫描”。
6. 页面依次显示枚举文件、读取图片、计算指纹、相似分组和生成结果的进度。
7. 用户可以取消扫描；取消不会触发任何文件修改。

### 5.2 查看结果

1. 左侧展示相似组，可筛选全部、完全重复和视觉相似。
2. 用户选中一组后，右侧展示该组所有图片。
3. 每张图片显示缩略图、文件名、完整路径、尺寸、格式和文件大小。
4. 系统标注一张“建议保留”图片。
5. 用户可以打开图片、打开所在文件夹或复制完整路径。
6. 删除复选框默认全部未选中。
7. 用户可以逐张勾选，也可以主动点击“保留建议项并选择本组其他图片”。

### 5.3 移入回收站

1. 底部展示已选图片数量和所选文件总大小。
2. 用户点击“移入回收站”。
3. 二次确认窗口展示数量、总大小和每个文件的完整路径。
4. 窗口明确说明文件不会永久删除，清空回收站后才会真正释放相应空间。
5. 用户确认后，系统在重新校验每个文件后逐项调用回收站服务。
6. 成功项从结果中移除；失败或状态已变化的项保留并显示原因。
7. 某组只剩一张图片后，该组从相似结果中移除。

## 6. 技术路线选择

第一版采用“混合指纹方案”。

### 6.1 选择理由

- SHA-256 可以无歧义识别内容完全一致的文件。
- pHash 对缩放、格式转换和压缩较稳定。
- dHash 可以补充图像结构变化判断。
- 小尺寸灰度指纹用于最终像素级复核，降低纯色图、文字图或哈希碰撞产生的误报。
- 宽高比过滤可以主动排除大量裁剪图。
- BK-tree 可以按汉明距离搜索候选，避免一万张图片之间的全量两两比较。

### 6.2 未选择的方案

单一感知哈希实现更简单，但对纯色、文字和结构接近图片的误报控制不足。AI 图像向量能够识别语义相近内容，却容易把同一场景的不同照片归组，同时增加模型体积和部署复杂度，不适合以安全删除为目标的第一版。

## 7. 模块与文件边界

```text
tools/
├─ image_similarity_tool.py
└─ image_similarity/
   ├─ __init__.py
   ├─ models.py
   ├─ fingerprints.py
   ├─ grouping.py
   ├─ scanner.py
   └─ recycle_bin.py
```

### 7.1 `tools/image_similarity_tool.py`

职责：

- 构建第 5 个 PyQt6 标签页。
- 管理目录、递归选项、相似度预设和扫描命令。
- 显示分阶段进度、失败计数和取消状态。
- 使用 Qt model/view 展示相似组与图片明细。
- 管理用户勾选状态和删除二次确认。
- 将扫描与回收站服务结果转换为用户可理解的提示。

该文件不实现哈希算法，也不直接调用 `send2trash`。

### 7.2 `tools/image_similarity/models.py`

定义只包含数据和枚举的模型：

- `SimilarityPreset`：严格、标准、宽松。
- `ScanPhase`：枚举、视觉指纹、完整哈希、分组、缩略图、完成、取消。
- `ImageRecord`：路径、规范路径、大小、修改时间、稳定文件身份、格式、方向修正后尺寸等。
- `ImageFingerprint`：可选 SHA-256、pHash、dHash、灰度指纹和预乘 RGBA 描述符。
- `ExactCluster`：内容完全相同的图片集合。
- `SimilarityGroup`：组类型、代表图、成员和内部关系标签。
- `ScanFailure`：失败路径、结构化错误码和可显示原因。
- `RecycleItemResult`：成功、状态变化跳过、安全拒绝或执行失败。

### 7.3 `tools/image_similarity/fingerprints.py`

职责：

- 使用 `ImageOps.exif_transpose()` 统一 EXIF 方向。
- 读取方向修正后的尺寸和格式。
- 在固定白底上计算 pHash、dHash 和固定大小灰度指纹，并生成保留透明度与色度的 8×8 预乘 RGBA 描述符。
- 对同文件大小且可能重复的文件计算 SHA-256。
- 计算灰度相似度和宽高比差异。
- 保持 Pillow 的解压炸弹安全限制，并将 `DecompressionBombWarning` 作为可捕获的超大图片失败处理，不擅自关闭保护。

### 7.4 `tools/image_similarity/grouping.py`

职责：

- 将相同 SHA-256 的记录组成精确副本簇。
- 为每个精确副本簇选择代表图片。
- 使用 pHash BK-tree 查找视觉相似候选。
- 使用宽高比、dHash、灰度指纹和预乘 RGBA 描述符复核候选。
- 双哈希密集时按阈值使用 32 或 64 维灰度分块和 L1 下界索引缩小范围，再对下界候选执行原始 256 维灰度 L1 精确复核；灰度邻域仍然密集且全部指纹具有颜色描述时，惰性使用一组通道和、两组互补通道差的 32 或 64 维 RGBA 下界索引，并以原始 256 字节 RGBA L1 距离精确收口。每组投影内的两个坐标使用不重叠通道，按三角不等式形成原始 L1 的可靠下界。首次查询三组投影后按候选数量选择后续顺序，每个种子细化到交集不超过 512 项或三组投影全部用完；这既观察色度差异，也覆盖所有通道同步变化的透明度模式，并保持无漏报候选语义。
- 按代表图直接相似规则建立安全分组，不进行无限传递合并。
- 根据稳定质量排序选出建议保留项。

### 7.5 `tools/image_similarity/scanner.py`

职责：

- 在根目录下枚举支持的图片文件。
- 默认递归，但不跟随目录符号链接或 Windows 重解析点。
- 协调有界并发的图片读取与指纹计算。
- 检查取消标志并停止继续提交任务。
- 限制进度信号频率。
- 在分组完成后按需生成结果缩略图数据。
- 返回纯数据，不在工作线程中创建 `QPixmap`。

### 7.6 `tools/image_similarity/recycle_bin.py`

职责：

- 校验待处理路径仍位于本次扫描根目录内。
- 拒绝目录、符号链接、重解析目标和结果集之外的路径。
- 对比扫描快照中的文件大小、`mtime_ns` 和稳定文件身份，拒绝已变化或被替换文件。
- 在尽可能紧邻回收站后端调用的位置再次复核规范路径、链接组件和文件身份。
- 逐项调用 `Send2Trash`。
- 返回每个文件的结构化结果，不执行永久删除降级。

## 8. 支持格式与文件枚举

第一版支持：

```text
.jpg .jpeg .png .bmp .webp .tif .tiff
```

枚举规则：

- 扩展名匹配不区分大小写。
- 不跟随目录符号链接或 Windows 重解析点。
- 单个文件链接也不进入相似结果，避免删除实际位于根目录外的目标。
- 无权限目录记录一次失败并继续扫描其他目录。
- 扫描途中消失的文件记录为跳过。
- 不通过修改文件扩展名来猜测不受支持格式。

## 9. 指纹计算流程

### 9.1 元数据阶段

每个候选文件记录：

- 用户选择根目录下的原始路径。
- `resolve` 后的规范路径。
- 文件大小。
- `mtime_ns`。
- `st_dev`/`st_ino` 文件身份；Windows 对应卷与文件索引，用于识别同大小同时间的路径替换。
- 图像格式。
- EXIF 方向修正后的宽、高和像素总量。

### 9.2 完全重复

1. 先按文件大小分桶。
2. 只有同一大小桶内存在多个文件时才计算 SHA-256。
3. SHA-256 完全一致的文件组成 `ExactCluster`。

这样可以避免对明显不可能完全重复的单独文件进行额外整文件哈希。

### 9.3 视觉指纹

所有可正常解码的图片计算：

- 64 位 pHash。
- 64 位 dHash。
- 归一化固定尺寸灰度指纹。
- 8×8 预乘 RGBA 描述符；完全透明像素的隐藏 RGB 不参与比较，但透明度和可见色度差异会保留。
- 方向修正后的宽高比。

感知指纹基于方向修正后的图像，避免仅因 EXIF 方向不同而漏报。

### 9.4 初始预设阈值

以下数值是第一版工程初值，必须集中定义为可测试配置，不能散落在 UI 或算法中：

| 预设 | pHash 汉明距离 | dHash 汉明距离 | 宽高比差异 | 灰度相似度下限 |
| --- | ---: | ---: | ---: | ---: |
| 严格 | ≤ 4 | ≤ 4 | ≤ 1% | ≥ 94% |
| 标准 | ≤ 8 | ≤ 8 | ≤ 2% | ≥ 90% |
| 宽松 | ≤ 12 | ≤ 10 | ≤ 3% | ≥ 86% |

灰度相似度定义为：

```text
1 - mean(abs(pixel_a - pixel_b)) / 255
```

候选必须同时满足当前预设的全部条件。UI 只显示预设名称，不显示数值。
预乘 RGBA 描述符使用同一归一化平均绝对差公式和当前预设下限进行最终复核。

## 10. 索引与安全分组

### 10.1 BK-tree 候选搜索

- 每个精确副本簇只使用一张代表图加入 pHash BK-tree。
- 不属于精确副本簇的图片以单成员簇加入索引。
- 查询半径使用当前预设的 pHash 汉明距离。
- BK-tree 返回的候选再执行 dHash、宽高比和灰度指纹复核。
- 双哈希候选超过密度上限时，严格阈值使用 32 个、标准和宽松阈值使用 64 个灰度分块和构成低维 L1 下界索引；下界查询不会漏掉真实阈值内候选，交付分组前还要执行原始 256 字节精确 L1 复核。若灰度候选仍超过密度上限，则惰性建立三组严格 32 维、标准和宽松 64 维的 RGBA 通道下界索引，其中一组使用通道和观察共同变化，两组使用互补通道差观察色度变化。首个种子确定选择性顺序，后续种子按需取投影交集，交集与灰度候选均以原始描述精确过滤后才进入完整视觉复核。性能指标单独记录投影树实际交付数量，防止最终复核计数掩盖索引内部退化。

### 10.2 防止链式误合并

不使用简单连通分量无限扩展相似组。采用代表图直接匹配规则：

1. 按建议保留质量顺序选择尚未分组的代表图作为组种子。
2. 只把与该种子直接通过全部阈值的候选加入当前组。
3. 候选之间的相似关系不能继续把与种子不相似的新图片传递进组。
4. 精确副本簇在最终展示时展开为全部成员。

若一个组的全部成员 SHA-256 相同，组类型为“完全重复”；只要包含不同内容哈希但视觉相似的成员，组类型为“视觉相似”，组内精确副本继续显示“完全重复”关系标记。

### 10.3 建议保留排序

建议保留项使用稳定顺序：

1. 能正常完整解码。
2. 方向修正后的像素总量更大。
3. 像素总量相同时文件大小更大。
4. 仍相同时按规范路径不区分大小写排序。

该排序只生成建议标记，不自动设置删除复选框，也不阻止用户选择建议保留项。

## 11. 后台执行与取消

### 11.1 线程模型

- `ImageScanWorker` 运行在独立 `QThread`。
- 工作线程内部可使用有界执行池并行读取和计算指纹，初始最大并发不超过 4。
- 所有结果按枚举序号恢复稳定顺序，不能因并发完成顺序改变分组结果。
- 工作线程通过信号发送阶段、计数、失败和最终纯数据结果。
- 同大小候选的 SHA-256 使用独立“完整哈希”阶段报告已处理数量，避免大文件批次看似停滞。
- `QPixmap`、控件模型更新和消息框只在 Qt 主线程执行。

### 11.2 进度

进度至少包含：

- 当前阶段。
- 已处理数量和总数。
- 当前失败数量。
- 百分比进度。

进度信号刷新频率限制在每秒最多 10 次，避免大量小文件导致事件队列拥塞。

### 11.3 取消

- 取消使用线程安全标志，不强制终止线程。
- 停止提交新文件任务。
- 当前正在处理的图片完成关闭后退出。
- 已计算的中间结果不进入正式结果页。
- 取消不会调用回收站服务或修改用户文件。

## 12. UI 设计

### 12.1 页面结构

标签页名称：`图片相似度检测`。

页面由两个分离的半透明悬浮区域组成：

1. 扫描设置与进度区。
2. 相似组与图片明细结果区。

两个区域之间保留间距，根页面和间距处继续显示当前壁纸。

### 12.2 扫描设置区

包含：

- 根目录只读输入框。
- “选择文件夹”按钮。
- “包含子文件夹”复选框，默认选中。
- 严格、标准、宽松单选项，默认严格。
- “开始扫描”和“取消扫描”按钮。
- 阶段文字、进度条、已处理/总数和失败数。

### 12.3 结果区

结果区使用 Qt model/view，而不是为每张图片创建永久 QWidget 卡片。

- 左栏使用组模型，支持全部、完全重复和视觉相似筛选。
- 组摘要显示代表缩略图、成员数量、组内文件总大小和类别。
- 右栏使用图片明细模型，显示复选框、缩略图、元数据和操作按钮。
- 缩略图按可见项懒加载，并使用有容量上限的内存缓存。
- 双击缩略图调用系统默认图片查看器。
- 提供打开所在文件夹和复制完整路径操作。

### 12.4 删除选择

- 初始没有任何选中项。
- 每张图片只能由用户主动勾选。
- 提供“保留建议项并选择本组其他图片”，但不提供跨全部结果的一键选择。
- 底部实时显示已选数量和所选文件总大小。
- 没有选中项时，“移入回收站”按钮禁用。

### 12.5 二次确认窗口

确认窗口必须显示：

- 选中图片总数。
- 所选文件总大小。
- 可滚动的完整路径清单。
- “文件将移入系统回收站，不会永久删除”的明确说明。
- “只有清空回收站后才会真正释放空间”的说明。

默认焦点不能放在确认删除按钮上，避免回车误触。

## 13. 动态主题与背景可见性

新页面必须复用 `tools/theme_utils.py` 的动态主题生成，不维护独立硬编码配色。

具体约束：

- 标签页根控件背景透明。
- 外层 `QScrollArea`、viewport 和内容控件三层全部透明。
- 扫描区和结果区使用现有 `QFrame#container` 的半透明背景、圆角边框和 `apply_shadow()`。
- 不使用覆盖整个标签页的不透明白色或黑色面板。
- `QTreeView`、`QListView`、进度条、结果行、悬停和选中颜色由当前壁纸主题变量生成。
- 缩略图仅在自身小范围内使用必要背景。
- 切换壁纸后，新页面和现有工具同步刷新主题。
- 850×700 默认窗口下完整可用；更小窗口通过透明滚动区访问，不裁切关键操作。

主题验证必须覆盖浅色壁纸、深色壁纸和无壁纸回退三种情况。

## 14. 删除前安全复核

每个待处理文件必须依次通过：

1. 路径仍存在。
2. 路径是普通文件。
3. 路径不是符号链接或重解析目标。
4. 规范路径仍位于本次扫描根目录内。
5. 路径存在于本次正式扫描结果中。
6. 当前文件大小与扫描快照一致。
7. 当前 `mtime_ns` 与扫描快照一致。
8. 当前卷/设备和文件索引与扫描快照一致。

在调用路径型回收站后端前重复执行规范路径、链接组件和文件快照复核。该复核可显著缩小路径重开竞态窗口；`Send2Trash` 只接收路径，因此不宣称提供跨后端的绝对原子文件句柄保证。

任一条件不满足时，结果为“跳过”，提示用户重新扫描。不能因为复核失败而降级到永久删除或继续处理不确定路径。

## 15. 回收站结果处理

- 使用 `Send2Trash` 逐项处理。
- 每个文件独立返回成功、状态变化跳过、安全拒绝或执行失败。
- 一个文件失败不回滚已经进入回收站的其他文件，也不阻止后续文件。
- 成功项从当前结果模型移除。
- 失败和跳过项保留，并显示可复制的原因。
- 只剩一个成员的组从相似组列表移除。
- 当前会话保留最近一次操作摘要，支持复制；第一版不把用户本地路径写入持久日志文件。

## 16. 结构化错误

扫描失败至少区分：

```text
PERMISSION_DENIED
DECODE_FAILED
IMAGE_TOO_LARGE
FILE_DISAPPEARED
UNSUPPORTED_IMAGE
SCAN_CANCELLED
UNKNOWN_SCAN_ERROR
```

回收站结果至少区分：

```text
MOVED_TO_TRASH
SKIPPED_CHANGED
SKIPPED_UNSAFE_PATH
TRASH_OPERATION_FAILED
```

UI 使用用户可理解的中文说明，详细异常仅用于诊断，不让单个异常终止整个批次。

第一版预计新增：

- `ImageHash`：pHash 和 dHash。
- `Send2Trash`：跨平台移入系统回收站。

## 18. 自动测试设计

### 18.1 指纹测试

- 相同字节得到相同 SHA-256。
- 同图 PNG/JPEG 转换、缩放和不同压缩质量在对应阈值下通过。
- 轻微色彩变化在视觉相似范围内。
- EXIF 方向不同但视觉一致的图片可以识别。
- 明显裁剪、不同构图、不同连拍动作和不同宽高比在严格模式下被拒绝。
- 纯色图和文字图不会仅凭单一哈希直接判定。

### 18.2 预设测试

- 严格、标准、宽松的候选集合保持单调递增。
- UI 只能选择预设，不能注入任意距离值。
- 阈值集中定义且每项均被测试覆盖。

### 18.3 分组测试

- 完全重复文件形成精确副本簇。
- 精确副本与其压缩版可以展开到同一视觉相似组。
- A 与 B 相似、B 与 C 相似但 A 与 C 不相似时，C 不能仅靠传递关系进入 A 的组。
- 建议保留排序稳定且可重复。
- 并发完成顺序不影响结果顺序和分组。

### 18.4 扫描测试

- 递归开关生效。
- 符号链接和重解析路径不进入结果。
- 损坏、无权限、消失和超大图片不会中断其他文件。
- 取消后不生成正式结果，也不触发文件操作。
- 进度计数和最终统计一致。

### 18.5 回收站服务测试

- 自动测试注入假回收站后端，不真实删除用户文件。
- 未变化且安全的普通文件会调用后端一次。
- 文件大小、修改时间或稳定文件身份变化时跳过。
- 最终复核发现路径或文件身份漂移时不调用后端。
- 根目录外路径、目录和链接被拒绝。
- 单项失败不阻止后续项。
- 不存在永久删除后备路径。

### 18.6 UI 与主题测试

- 主窗口出现第 5 个标签页。
- 默认包含子目录、默认严格模式、默认无删除选择。
- 未选择文件时回收站按钮禁用。
- 二次确认包含数量、总大小、完整路径和回收站说明。
- 扫描期间主窗口保持响应并可取消。
- 浅色、深色和无壁纸模式中文字可读。
- 标签根控件及滚动区域三层保持透明。
- 切换壁纸后控件使用新主题颜色。

### 18.7 性能测试

- 使用一万条合成指纹验证候选搜索不执行全量平方级比较。
- 记录候选复核次数，确保索引确实缩小搜索范围。
- 缩略图缓存容量受控，不随扫描图片总数无界增长。
- 队列满时的可见缩略图进入有界延迟队列，旧代次同路径任务不得占用新代次请求。
- 性能测试不依赖某台机器的固定秒数，但应验证算法复杂度和 UI 信号节流。

## 19. 手工验收

使用一次性测试目录准备：

- 完全相同副本。
- PNG/JPEG 格式转换副本。
- 不同分辨率和 JPEG 压缩质量副本。
- 轻微色彩变化副本。
- 明显裁剪图。
- 同场景不同连拍图片。
- 损坏图片和无权限路径。

验收步骤：

1. 扫描期间移动窗口、切换标签并执行取消，界面不冻结。
2. 切换浅色和深色壁纸，确认背景持续可见且文字可读。
3. 检查完全重复和视觉相似分类符合预期。
4. 确认所有删除项默认未选中。
5. 确认完整路径和所选总大小在二次确认中可见。
6. 在确认前修改一个测试文件，验证它被跳过并要求重新扫描。
7. 将一次性测试图片移入回收站，并从系统回收站恢复。
8. 制造一个回收站处理失败项，确认其他项仍继续且原因可见。

真实回收站测试只能使用明确创建的一次性测试图片，不能使用用户来源不明文件。

## 20. 完成标准

第一版只有同时满足以下条件才算完成：

- 扫描阶段对用户文件完全只读。
- 完全重复和视觉相似分组稳定且可解释。
- 严格模式优先减少误报。
- 不存在自动选择删除、永久删除或失败后永久删除降级。
- 只有用户明确选中并二次确认的未变化文件会进入回收站。
- 单项失败不会破坏整个批次结果。
- 一万张图片目标规模不采用平方级全量比较。
- UI 与现有动态壁纸主题一致，背景图保持可见。
- 自动测试全部通过。
- 使用一次性图片完成真实回收站手工验证和恢复验证。

## 21. 风险与缓解

| 风险 | 缓解措施 |
| --- | --- |
| 感知哈希误报 | 组合 pHash、dHash、宽高比、灰度和预乘 RGBA 复核；默认严格；不自动选择删除 |
| 感知哈希漏报 | 提供标准和宽松预设；结果仍由用户人工判断 |
| 相似关系链式扩大 | 只接受与组代表图直接匹配的成员 |
| 扫描期间文件变化 | 删除前比较路径、大小、`mtime_ns` 和稳定文件身份，并在调用后端前最终复核 |
| 路径越界或链接目标 | 不扫描链接；删除前再次规范化并验证根目录边界 |
| 大量缩略图占用内存 | 结果阶段懒加载并使用有界 LRU 缓存与有界延迟请求队列 |
| UI 更新过于频繁 | 进度信号限制为每秒最多 10 次 |
| 回收站后端不可用 | 返回明确失败，不降级永久删除 |
| 用户误以为已释放空间 | 显示“所选总大小”，说明清空回收站后才释放空间 |
