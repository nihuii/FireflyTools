## 2. 项目速览

FireflyTools（流萤媒体工具箱）是 Python 3.10+ / PyQt6 桌面应用，主入口：

```powershell
python -m tools.main
```

四个 UI 模块：

- 视频下载爬虫：网页嗅探、MP4/HLS/DASH 下载、队列、诊断和错误报告。
- 视频子目录提取：把深层视频移动到指定根目录。
- 关键字归档：按文件名关键字整理图片和视频。
- 图片智能裁剪：基于 Pillow 批量缩放和裁剪。

当前开发重点是视频下载爬虫：

```text
UI/队列       tools/video_downloader.py
核心编排      tools/video_crawler/spider.py
网页嗅探      tools/video_crawler/sniffer.py
HLS 下载      tools/video_crawler/adapters/hls.py
DASH 下载     tools/video_crawler/adapters/dash.py
断点状态      tools/video_crawler/resume.py
```

依赖包括 PyQt6、Pillow、requests、aiohttp、m3u8、cryptography、Playwright 和 yt-dlp。

Windows FFmpeg 保存在 `tools/ffmpeg.exe`。导入 `tools` 时，`tools/runtime_setup.py` 会把 `tools/` 加到子进程 `PATH` 首位。Linux/macOS 需自行安装 FFmpeg。

必须从项目根目录启动。`downloads/`、`temp/`、`browser_profiles/` 都是相对当前工作目录解析；从 `tools/` 启动会把产物写到 `tools/downloads/` 等位置，曾因此出现“日志成功但根目录找不到视频”的误解。

## 5. UI 当前状态

- 无边框圆角主窗口，标题栏支持最小化、最大化、关闭和壁纸切换。
- 右下角有 `QSizeGrip`，窗口可拖动缩放。
- `pic/` 中全部 JPG/PNG 作为壁纸，`theme_utils.py` 根据壁纸生成主题。

- 下载任务会快照并发数、稳定/高速模式、断点续传、yt-dlp、直播秒数和嗅探选项，后台线程按队列顺序执行。
- 批次弹窗按结构化错误码汇总，仅对 `retryable=True` 的失败提供重试。

相关测试：`tests/test_main_window.py`、`tests/test_theme_utils.py`、`tests/test_video_downloader.py`。

## 6. 爬虫架构与执行流程

核心模型在 `models.py`：

- `MediaKind`：MP4、HLS、DASH、DRM、UNKNOWN。
- `MediaCandidate`：候选 URL、来源、分数、切片数、码率等。
- `BrowserSessionSnapshot`：UA、Referer、Origin、Cookie、Header、LocalStorage。
- `SnifferOptions`：无头/可视化、持久 profile、等待秒数。
- `DiagnosticReport`：候选流、会话、警告和错误。
- `VideoDownloadError`：错误码、消息、详情和 `retryable`。

适配器优先级：Direct MP4 100、HLS 80、DASH 60。yt-dlp 是 UI 控制的外部后备，不在默认 orchestrator 中。

一次网页下载大致经过：

1. `UniversalVideoSpider.run()` 判断 MP4/M3U8/MPD 直链或普通网页。
2. 普通网页由 `PageSniffer` 使用 Playwright 监听媒体请求。
3. 嗅探器记录页面状态并从网络 URL、content-type、JSON/HTML/JS 响应正文提取候选。
4. 过滤 `https://host/\.m3u8` 等脚本正则占位符，保留合法 JSON 转义 URL。
5. 捕获允许继承的 Cookie/Header/LocalStorage，供下载请求复用。
6. 多个 M3U8 候选先探测正片和画质，再交给对应适配器。
7. 下载后验证输出存在且非空，否则返回 `EMPTY_OUTPUT`。

## 7. Playwright 嗅探现状

`PageSniffer` 支持无头和可视化 Chromium、人工操作等待、可选持久化 profile、页面状态诊断、网络媒体监听和响应正文提取。

重要等待规则：

- 网络层捕获到真实媒体请求可以提前结束等待。
- 仅从响应正文发现候选不视为可靠证据，不会立即结束等待。
- 主页面 403 或明显访问受限返回 `HTTP_FORBIDDEN`，而不是笼统的 `NO_MEDIA_FOUND`。

持久化 profile 默认位于 `./browser_profiles/video_crawler`，可能含 Cookie 和站点存储，禁止加入 Git。程序不自动破解验证码，也不绕过登录、付费、地区或 DRM 限制。

## 8. M3U8 正片与画质选择

`spider.py::_select_best_m3u8()` 会请求每个候选；若为 master playlist，则读取最高带宽/分辨率变体，再统计媒体切片。直接流还会从 `/3000k/` 等 URL 片段推断码率。

正片容差：

```text
max(3, 最大切片数的 5%)
```

在接近最大切片数的候选中，按码率、分辨率像素数、切片数排序。因此三个候选同为约 368 个切片时，不会默认选择第一个。

若全部候选都无法验证，不再降级使用“最后捕获的 M3U8”，而是返回 `NETWORK_TIMEOUT` 或 `M3U8_PARSE_FAILED`。

## 9. 下载能力边界

### HLS

支持 TS、fMP4/`EXT-X-MAP`、AES-CBC、显式/默认 IV、BYTERANGE、DISCONTINUITY、多 init map、默认音轨、WebVTT 字幕、直播 playlist、并发/退避、切片级断点续传和 FFmpeg 修复。失败切片不超过 3% 时允许继续合并。

### DASH

支持无 DRM 静态 MPD、`SegmentTemplate`、最高带宽音视频轨、分段下载、track manifest 续传和 FFmpeg mux。不支持动态 MPD、`SegmentTimeline`、DRM 绕过及复杂 BaseURL/缺轨场景。

### yt-dlp

仅当用户启用后备、内置错误为 `NO_MEDIA_FOUND` 或 `UNSUPPORTED_DASH`，且系统能找到 `yt-dlp` 时调用。403、网络超时和 HLS 解析失败不会无条件转交。

## 10. 错误、脱敏与安全边界

错误码：

```text
UNKNOWN  NETWORK_TIMEOUT  HTTP_FORBIDDEN  HTTP_NOT_FOUND
NO_MEDIA_FOUND  UNSUPPORTED_DASH  UNSUPPORTED_DRM
M3U8_PARSE_FAILED  SEGMENT_FAILURE_RATE_EXCEEDED
FFMPEG_FAILED  EMPTY_OUTPUT
```

新增失败路径应优先抛出 `VideoDownloadError`，不要让 requests/aiohttp/m3u8/subprocess/WinError 直接落入 `UNKNOWN`。日志、诊断报告和弹窗通过 `redact_for_display()` 隐藏 Cookie、Authorization、token、signature 等敏感内容。

项目明确不做 DRM 绕过、验证码破解、权限/付费墙突破或恶意高并发请求。

## 11. 近期调试结论

- 页面正文中的 `https://www.aowu.tv/\.m3u8` 是正则占位符，不是真实流；当前已过滤。
- 旧逻辑会在 M3U8 探测全失败后继续下载并最终报 WinError 10060；当前在选择阶段返回结构化超时/解析错误。
- 切片数量只用于识别正片，不代表画质；当前已加入带宽、分辨率和 URL 码率线索。
- 输出目录取决于进程 CWD。排查“成功但找不到文件”时，先检查启动目录、UI 保存路径和日志中的绝对路径。
- FFmpeg 成功后可能出现 `WinError 145: 目录不是空的`。这通常是非致命清理警告，不应覆盖已成功生成的视频。

尚未完全解决的风险：`resume.py::SegmentManifest.save()` 使用固定 `.firefly-segments.json.tmp` 后执行 `os.replace()`。Windows 文件占用可能触发 WinError 5。后续应先写测试，再实现唯一临时文件名、PermissionError 重试和结构化文件访问错误。
