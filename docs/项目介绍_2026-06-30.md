核心变化：

- 广告或推荐 MP4 即使是真实 network 响应，也不再提前结束 Playwright 等待；只有 network HLS 能提前结束，其他情况等待到 `manual_wait_seconds` 上限。

## 3. 项目定位

FireflyTools（流萤媒体工具箱）是一个 Python 3.10+ / PyQt6 桌面媒体工具箱。

主入口：

```powershell
python -m tools.main
```

主窗口类：

```text
tools/main.py -> MediaToolboxApp
```

当前提供四个 UI 模块：

1. 视频下载爬虫：网页嗅探、MP4/HLS/DASH 下载、队列、诊断、断点恢复和错误报告。
2. 视频子目录提取：把深层目录中的视频移动到指定根目录。
3. 关键字归档：按文件名关键字整理图片和视频。
4. 图片智能裁剪：基于 Pillow 批量缩放、居中或按顶部/底部对齐裁剪。

当前开发重点是视频下载爬虫：

## 7. 爬虫核心模型

文件：`tools/video_crawler/models.py`

主要类型：

- `MediaKind`：`DIRECT_MP4`、`HLS`、`DASH`、`DRM`、`UNKNOWN`。
- `MediaCandidate`：候选 URL、类型、来源、可信分数、Content-Type、切片数、带宽等。
- `BrowserSessionSnapshot`：User-Agent、Referer、Origin、Cookie、允许继承的 Header、LocalStorage。
- `PageAccessSnapshot`：主页状态码、标题、最终 URL、video/iframe 数量。
- `SnifferOptions`：无头/可视化、持久 profile、等待秒数。
- `DiagnosticReport`：候选流、会话、警告和错误。

重要区分：

- `MediaCandidate.score` 表示候选证据可信度，不代表视频画质。
- `segment_count` 更接近内容时长线索，不代表画质。
- `bandwidth` 和分辨率才是画质排序的重要指标。
- LocalStorage 会被记录，但当前不会自动全部转换为下载请求头。

结构化异常位于 `tools/video_crawler/errors.py`：

- `VideoErrorCode`：稳定错误码。
- `VideoDownloadError`：错误码、用户消息、详情和 `retryable`。

## 8. 适配器架构

文件：`tools/video_crawler/adapters/base.py`

`VideoAdapter` Protocol 约定：

```text
can_handle(candidate)
download(candidate, output_filename)
diagnose(url)
```

`VideoDownloadOrchestrator` 先让候选解析器返回统一 `MediaCandidate`，再按优先级选适配器：

```text

```

`YtDlpAdapter` 是 UI 控制的外部后备，不在默认 orchestrator 列表中。

这种拆分使 UI 不需要理解 HLS AES，HLS 下载器也不需要知道 PyQt 控件。

## 10. Playwright 网页嗅探

文件：`tools/video_crawler/sniffer.py`

`PageSniffer` 支持：

- 无头或可视化 Chromium。
- 可选持久化 profile。
- 页面状态码、标题、最终 URL、video/iframe 数量诊断。
- 监听页面 response 事件。
- 根据 URL 和 Content-Type 分类 MP4、M3U8、MPD、DRM。
- 从 JSON、HTML、JavaScript 响应正文提取媒体 URL。
- 还原 `\/`、`\u002F`、`\u0026` 等转义。
- 过滤 `https://host/\.m3u8` 这类并非真实地址的正则模板。
- 模拟点击 video 或页面中心以触发媒体请求。
- 捕获浏览器 Cookie、请求 Header 和 LocalStorage。

等待规则：

- 只有真实 network HLS 是最高优先级终止证据，可以提前结束等待。
- network MP4、network DASH 和所有 response-body 候选都不能提前结束；若没有 HLS，继续等待到 `manual_wait_seconds` 上限。
- 只在响应正文中发现 URL 字符串不算可靠证据，仍会继续等待播放器实际请求。
- 等待结束日志会说明是捕获 network HLS 还是达到时间上限，并输出按类型/来源统计的候选数量。
- 主页返回 403 或标题明显表示访问受限时，抛出 `HTTP_FORBIDDEN`。

持久化 profile 默认路径：

```text
./browser_profiles/video_crawler
```

该目录可能包含 Cookie 和站点存储，禁止加入 Git。

## 11. 浏览器会话继承

文件：`tools/video_crawler/session.py`

下载请求会继承：

- 浏览器 User-Agent。
- 来源页面 Referer。
- 页面 Origin。
- 与目标域名匹配的 Cookie。
- allowlist 中的 Authorization、Accept、Accept-Language、Range、X-Token、X-Auth-Token。

不会把任意捕获请求头全部转发，避免跨域泄露敏感信息。

浏览器会话不仅用于最终媒体下载，也用于 M3U8 playlist 探测和 MP4 HEAD/Range 元数据探测。否则某些 CDN 会对缺少 Referer、Origin 或 Cookie 的 Python 请求返回 403，即使浏览器内已经成功播放。

所有日志、诊断和弹窗应经过 `redact_for_display()`，隐藏 Cookie、Authorization、token、signature 等内容。

## 12. M3U8 正片与画质选择

入口：`tools/video_crawler/spider.py::_select_best_m3u8()`

网页可能同时暴露广告、预告、多个 CDN 地址和多个清晰度。当前选择分两步：

1. 探测每个候选的有效性和切片数。
2. 在接近最大切片数的候选中，按带宽、分辨率像素数和切片数排序。

正片容差：

```text
max(3, 最大切片数的 5%)
```

如果候选是 master playlist，先读取最高带宽/分辨率 variant，再统计 media playlist 的切片。

直接 media playlist 还会从 `/3000k/` 等 URL 片段推断码率。

playlist 探测使用 15 秒超时，并按每个候选域名继承浏览器会话 Header。该值高于旧版 5 秒：现场目标的 playlist 在同一环境中曾约 8.9 秒才返回 200，5 秒会把可用正片误判为网络超时。

因此：

- 切片数量相同不代表画质相同。
- 三个候选均为约 368 个切片时，不会简单选择第一个。
- 若所有候选无法验证，不会再使用“最后捕获的 M3U8”，而是返回 `NETWORK_TIMEOUT` 或 `M3U8_PARSE_FAILED`。

## 13. MP4、HLS、DASH 和 yt-dlp

### 13.1 Direct MP4

文件：`tools/video_crawler/adapters/direct_mp4.py`

- 使用 `requests.get(stream=True)`。
- 以 1 MiB chunk 流式写入，避免把大视频全部载入内存。
- 有 Content-Length 时记录下载进度。
- 最终验证输出文件存在且非空。

网页嗅探降级到 MP4 前还会执行候选验证：

- 同一 URL 的 response-body/network 记录先去重并升级证据来源。
- 使用 HEAD 获取 Content-Length；HEAD 不支持或缺少大小时，用单字节 Range 请求读取 Content-Range 总长度。
- 不设置固定最小文件大小，避免误伤合法短视频；大小仅用于多个候选之间比较。
- response-body-only MP4 若无法验证，不会直接下载。

### 13.2 HLS

文件：`tools/video_crawler/adapters/hls.py`

当前主路径支持：

- master/media playlist。
- 最高带宽 variant 选择。
- TS 切片。
- fMP4 和 `EXT-X-MAP` 初始化片段。
- AES-CBC、显式 IV 和基于 media sequence 的默认 IV。
- `EXT-X-BYTERANGE` 与 HTTP Range。
- asyncio/aiohttp 并发下载、Semaphore 限流、重试与退避。
- 默认音轨和 WebVTT 字幕下载与 mux。
- 无 `ENDLIST` 直播 playlist 的定时录制。
- `.firefly-segments.json` 切片级断点续传。
- 失败切片不超过 3% 时继续合并。
- FFmpeg TS 合并、fMP4 容器修复和多轨 mux。

重要边界：

`group_fmp4_segments()`、`ordered_ts_segments()` 等 helper 和测试已经表达多 init map、DISCONTINUITY 的分组规则，但当前主下载路径尚未覆盖 HLS 标准允许的所有复杂组合。不要仅根据 helper 测试就断言复杂 playlist 已完全端到端支持。

### 13.3 DASH

文件：`tools/video_crawler/adapters/dash.py`

当前支持：

- 无 DRM 的静态 MPD。
- `Period -> AdaptationSet -> Representation` 解析。
- 最高带宽视频轨和音频轨。
- `SegmentTemplate` 的 `$RepresentationID$`、`$Number$` 展开。
- 初始化分段和媒体分段下载。
- video/audio 各自的 manifest 断点恢复。
- FFmpeg 将独立音视频轨 mux 为 MP4。

当前不支持：

- 动态或直播 MPD。
- `SegmentTimeline`。
- DRM 绕过。
- 缺少音轨或视频轨的复杂 MPD。
- DASH 标准中的全部 BaseURL 和模板变体。

### 13.4 yt-dlp

文件：`tools/video_crawler/adapters/ytdlp.py`

仅当以下条件同时成立时调用：

1. 用户启用了 yt-dlp 后备。
2. 内置路径错误码是 `NO_MEDIA_FOUND` 或 `UNSUPPORTED_DASH`。
3. 系统能找到 `yt-dlp`。

403、网络超时、HLS 解析失败和 DRM 不会无条件转交 yt-dlp。

## 14. 断点续传

文件：`tools/video_crawler/resume.py`

`SegmentManifest` 保存每个切片的 URL 和大小。恢复时需要同时满足：

- 切片文件存在。
- 文件大小大于 0。
- manifest 中存在记录。
- 当前大小与记录大小一致。

HLS 失败且启用恢复时保留临时切片；成功后才清理。DASH 的 video/audio 轨各自维护 manifest。

尚未完全解决的风险：

`SegmentManifest.save()` 使用固定 `.firefly-segments.json.tmp` 写入后调用 `os.replace()`。Windows 文件占用或安全软件扫描可能导致 WinError 5。后续修复应先写测试，再考虑唯一临时文件名、PermissionError 重试和结构化文件访问错误。

## 15. FFmpeg 与输出验证

FFmpeg 主要用于 mux/remux，不是网页嗅探器：

- TS 切片通过 concat demuxer 合并。
- fMP4 先拼接 init 和媒体片段，再用 FFmpeg 修复容器。
- DASH 独立视频轨、音频轨通过 `-c copy` mux。
- HLS 独立音频、字幕通过 `-map` 选择轨道。

`-c copy` 表示尽量不重新编码。

每条成功路径都应验证最终文件存在且大小大于 0，否则返回 `EMPTY_OUTPUT`。

FFmpeg 成功后偶尔出现：

```text
WinError 145: 目录不是空的
```

这通常是非致命清理警告。先确认最终输出验证结果，不要让清理异常覆盖已成功生成的视频。

## 17. 安全和合法边界

项目明确不做：

- Widevine、FairPlay、PlayReady 或其他 DRM 绕过。
- 验证码破解。
- 登录、付费墙、账号权限或地区限制突破。
- 恶意高并发请求。
- 敏感 Cookie、Authorization、token 或浏览器 profile 上传 Git。

可视化嗅探只允许用户在浏览器中完成站点许可的人工操作，并不保证绕过访问策略。

## 18. 近期调试结论

- `kanav.ad` 页面会同时暴露多个广告/推荐 MP4 和一个延迟出现的正片 HLS。旧版因 `networkidle` 常等待到 25 秒超时而偶然捕获 HLS；新版曾在首个 network MP4 出现后立即关闭浏览器，形成时序竞态。
- 当前通过“仅 network HLS 可提前终止 + 其他候选等满观察窗口”消除该竞态，不依赖 `networkidle` 超时作为正常控制流。
- 正片 HLS `cdn16.11yun.space/GAV1/328752/328752.m3u8` 在缺少浏览器来源头时现场返回 403；继承 Referer/Origin/Cookie 后可返回 200 并识别 266 个切片。
- 同一 playlist 在现场曾约 8.9 秒返回，旧 5 秒候选探测超时不足；当前统一使用 15 秒。
- `https://www.aowu.tv/\.m3u8` 是脚本正则模板，不是真实流，当前已过滤。
- 旧逻辑会在 M3U8 探测全部失败后继续下载并最终报 WinError 10060；当前在候选选择阶段返回结构化超时或解析错误。
- 切片数量用于识别正片，不代表画质；当前同时使用带宽、分辨率和 URL 码率线索。
- 输出目录取决于进程 CWD。排查“成功但找不到文件”时，先检查启动目录、UI 保存路径和日志中的绝对路径。
- 浏览器中能播放不等于 Python 请求必然可下载，媒体服务器仍可能检查 Cookie、Referer、Origin、Authorization 或短期 token。
